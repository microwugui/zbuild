## 根因：为什么 R14 的 4.4× 没有兑现

R14 是 **TS 侧同构 AST 微基准**（每节点同形、无转瞬分配），AST 表示几乎等于全部内存，故 88B→20B = 4.4×。
真实 `_tsc.js` 构建的 pprof（`alloc_space`）显示：

- AST node 字面量分配合计仅 **20.01MB / 156.5MB = 12.8%**；
- 真正的大头是 scope/symbol 表的 slice 增长（~20%）、printer（~15%）、文件 IO（~9%）——都不是 AST 节点表示；
- 小节点已由 Go tiny allocator 打包（多个塞进 16B），逐节点 malloc 的本征开销本就极小。

因此即便**完美消除** AST 节点表示的全部开销，理论上界也远低于 10%；竞技场实测 +0.32% 与此一致。
「去 interface + 扁平 struct」即便做完整 706 处改造，针对的仍是这 12.8% 的子集，且 M1 已证明字面摊平 64 字段
反而更大。继续投入 M2-b/c 属于无根因支撑的盲改，不予采纳。
